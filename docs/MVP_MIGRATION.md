# Задания и переводы MVP

Изменения в двух репозиториях нужно выпускать вместе: старый Android-клиент несовместим с новым TaskDto. Навигация, курсы, модули и связи M:N сохраняются. Схема drawio содержит старые поля и опечатки; V9 следует readme.txt, сохраняя фактические имена первичных ключей существующих таблиц.

## Переход существующей базы

1. Остановить запись в старый backend. Сделать резервную копию PostgreSQL (`pg_dump -Fc`) и восстановить её в отдельную тестовую базу.
2. Проверить версии Flyway: V1–V8 должны совпадать с репозиторием. Старые миграции не изменяются.
3. Запустить новый backend на копии. Flyway выполнит V9 в транзакции; Hibernate проверит схему через `ddl-auto=validate`.
4. Проверить количество пользователей, уроков, заданий и связей, пройти урок на новом клиенте. Только после этого повторить переход на рабочей базе и выпустить новый клиент.
5. При откате восстановить резервную копию и старый backend вместе со старым клиентом. Не запускать старый backend поверх V9.

V9 переносит title/theory_text в lesson_translations, question/explanation в task_translations, JSON-варианты в multiple_choice_options и option_translations. Все старые тексты считаются русскими. Если исходный контент многоязычный, перед переходом требуется отдельно разметить его язык. Идентификаторы, порядок lesson_tasks и пользовательский прогресс не меняются. Исходные payload заданий остаются в legacy_task_payloads для сверки.

Типы преобразуются: `test → MULTIPLE_CHOICE`, `write → CODING`, `finish → FILL_BLANK`. У FINISH раньше не было экрана: его вопрос сохраняется, окружение пропуска остаётся пустым и заполняется редактором контента. Старый WRITE трактуется как Java; задания других языков нужно проверить и указать programming_language после миграции.

Миграция останавливается при неизвестном типе, пустом эталоне, нестроковых JSON-вариантах либо отсутствии единственного совпадения correct_answer с вариантом теста. Исправьте исходные данные и повторите запуск; не обходите проверку через Flyway repair. Проверяются также удалённые задания, чтобы не потерять их данные.

## Данные новой схемы

- languages — языки учебного контента, отдельно от языков программирования; ru активен, en создан неактивным.
- users.language_id — выбранный язык; по умолчанию ru.
- lesson_translations, task_translations, option_translations — UNIQUE(объект, язык), иначе дубликат отклоняет PostgreSQL. При отсутствии перевода API возвращает русский текст.
- tasks — базовые поля; каждый тип должен иметь соответствующую подтаблицу с тем же task_id. Создавайте базовую запись и подтип в одной транзакции.
- multiple_choice_tasks/options — один или несколько правильных вариантов; порядок вариантов задаётся order_index. API принимает ID, а не текст варианта.
- fill_blank_tasks дополнена correct_answer и case_sensitive: без них схема из readme не позволяет проверить ответ.
- coding_tasks — starter_code, solution_code, programming_language. MVP сверяет исходный текст с эталоном с учётом регистра и внутренних пробелов, нормализует CRLF и внешние пробелы. Это не компиляция и не проверка эквивалентных решений. Формулируйте такие упражнения как точное воспроизведение команды. Новый исполнитель кода сюда не подключён.
- task_attempts — серверные отметки успешно выполненных заданий по пользователю и уроку. Завершение урока требует всех текущих заданий; повторный запрос завершения идемпотентен и повторно не начисляет XP. Отметки сохраняются между сессиями.

Задания не публикуются через CRUD API. При ручном редактировании проверяйте наличие ровно одного соответствующего подтипа, русского перевода, непустого эталона и корректных вариантов. После изменения эталонов сбросьте связанные task_attempts для повторной проверки. Для учебного релиза не включайте язык до наполнения переводов. Интерфейс Android остаётся русским; выбор языка меняет контент уроков и заданий.

## API

Все запросы требуют Authorization: Bearer JWT.

- GET /api/languages — активные языки.
- PUT /api/users/language/{languageId} — сохранить активный язык (неактивный → 400).
- GET /api/users/me — дополнен languageId.
- GET /api/modules/incourse/{id} — локализованные title/theoryText уроков.
- GET /api/tasks/bylesson/{lessonId} — упорядоченные задания без correctAnswer, solutionCode, isCorrect. options: [{id,text}], multipleSelect, starterCode, programmingLanguage, sentenceBefore/sentenceAfter.
- POST /api/tasks/{taskId}/check — {lessonId,optionIds:[ID]} либо {lessonId,answer:"текст"}. Ответ: {correct,explanation,validationMode}. Режимы OPTION_SET, EXACT_TEXT, EXACT_SOURCE. Несуществующие/чужие ID вариантов и дубликаты → 400; задание вне урока → 404.
- POST /api/lesson/{lessonId}/completed — 409, пока не решены все задания; после успеха повторный вызов возвращает пустой список без новых наград.

## Проверка и демо

JDK 21: `bash mvnw test`. Тесты запускают настоящий временный PostgreSQL 14 без Docker через embedded-postgres. Покрыты перенос V8→V9, откат некорректной миграции, проверка схемы Hibernate, порядок, отсутствие эталонов в DTO, выбор набора ответов, регистр, сохранение попыток и языки.

`psql -v ON_ERROR_STOP=1 -f docs/demo_content.sql` добавляет отдельный курс Java — MVP demo с одним уроком и тремя типами заданий. Скрипт не выполняется автоматически, повторный запуск не дублирует курс. Выберите этот курс в приложении; ответы: первые два варианта, println, System.out.println("Hello");. Английские переводы демоурока есть, язык остаётся неактивным до перевода остальных уроков.

На Android настройте BASEURL в RetrofitClient под адрес вашего backend. Проверьте: неверный ответ, верный ответ, выбор нескольких вариантов, потеря сети и повтор запроса, завершение урока, повторный запрос завершения, перезапуск приложения. Сборка: `bash gradlew assembleDebug` с Android SDK 36.
